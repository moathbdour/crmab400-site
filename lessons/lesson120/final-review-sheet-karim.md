## Extend Microsoft Power Platform (35–40%)

| ID | Topic | Rule | Trap | Lessons |

| E-01 | Pipeline stages | PreValidation (10) cancels on submitted values before the transaction; PreOperation (20) changes the Target inside it; PostOperation (40) acts on the saved row. Asynchronous steps exist only in PostOperation, run after commit and can't cancel. MainOperation (30) is for custom APIs and virtual table providers. | Cancelling in PreOperation or in an asynchronous step; external calls in a synchronous step | 65 |
| E-02 | Execution context | Read message, stage, mode, Target, images, SharedVariables, UserId and InitiatingUserId per request. UserId is the step's run-as identity, InitiatingUserId the real caller. Values shared in PreValidation are read from ParentContext.SharedVariables later. Never keep the context in a field. | UserId under impersonation; static fields; logic that depends on Depth or ParentContext order | 66, 68 |
| E-03 | Plug-in business logic | Rules that must hold for every caller go in a step on the real message (Close, not Update of statecode), with the rule itself in a pure class. | E-04 | Images | A pre-image holds stored values before the operation (none on Create); a post-image holds them after it (PostOperation only, none on Delete).
